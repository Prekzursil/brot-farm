Chapter 2

How it’s built — every choice and its rejected twin

Four Python files, ~600 lines, two dependencies (numpy, Pillow), no GPU, no compile step. The interesting parts are not the lines — they’re the forks in the road.

The architecture in one picture

Choice 1 — Two phases instead of one

Chosen: classify, then replay

Run the batch once to learn who escapes; then re-run only escapees, plotting as you go. Costs ~1.7× the arithmetic of a single pass.

Why: it keeps every inner operation a whole-array numpy expression. Vectorization demands uniform control flow — you cannot have per-point “start recording now” branches without falling out of SIMD-friendly array ops.

Rejected: single pass with orbit buffers

Record every orbit into per-sample arrays while iterating, then scatter once. Looks 40% cheaper on paper; in practice the recording gathers into Python-level lists or object arrays, memory balloons to GB, and the scatter dominates. There is a middle path — fixed per-sample ring buffers of 64 slots in a (N, 64) array — viable, but the code triples in complexity for a modest win on CPU.

Choice 2 — bincount instead of np.add.at

Turning point-coordinates into histogram hits is a scatter-add. The obvious tool, histogram += 1; np.add.at(hist, idx, 1), is notoriously slow — it’s a per-element ufunc with no vectorized fast path. np.bincount(flat_indices, minlength=W*H) does the same job at memory bandwidth. The cost is allocating a fresh 4M-entry array per call, so the plotter buffers indices and flushes at 24M points per bincount — amortizing the allocation to noise. Measured on this project’s workloads: bincount flushed in batches beat add.at by roughly an order of magnitude.

Choice 3 — compaction cadence

Points escape at wildly different times; after 30 steps a 3M-sample batch is mostly dead weight. Every k steps the survivors are compacted — boolean-masked down to the living — so work per step decays like the survival curve. k is a compromise: too small and the masking overhead (a full copy of six arrays) dominates; too large and you keep iterating corpses. k = 32 for quadratics, k = 8 for the transcendental mutations (they can overflow float64 in a handful of steps past their escape radii — which brings us to the bug).

The bug the tests caught

Symptom: quadratic-family renders (powers, ship, tricorn, celtic, buffalo, julia) came out sparse — 9–30% visible structure against the classic’s 62% — and ate mysterious amounts of phase-1 time.

Cause: a diverging point grows geometrically: past radius 2 a quadratic orbit takes ~11 more steps to overflow float64 into inf, and one step later inf − inf yields NaN. NaN fails every comparison — nan > 4 is False — so from that moment the escape test can never fire again: the point is misclassified as a prisoner forever, and it keeps riding along in the arrays burning cycles until the iteration cap. With compaction every 32 steps, roughly two-thirds of all escaping orbits were silently dropped from those maps.

Fix: one guard — (r > 4)0 | ~np.isfinite(r) — treat NaN as escaped. The original single-map renderer had it; the generalized farm rewrite dropped it. The regression test now compares the vectorized classifier against a per-step scalar reference on five maps. Corrective top-ups (~200M fresh samples under the fixed classifier) restored every affected histogram.

Moral: NaN is not a crash; it is a very quiet wrong answer. Floating-point escape tests need explicit infinite/NaN handling, and reference-test your fast path against a dumb one.

Choice 4 — analytic culling of the interior

Points inside the main cardioid or the period-2 bulb can never escape (a conjugacy argument pins their orbits to bounded disks), and both regions have closed-form membership tests. Culling them before iteration removes ~13% of samples from the Mandelbrot-family runs for free — sound because culled points contributed nothing to an escape-only histogram anyway. (The Antibuddhabrot must not cull: prisoners are its entire subject.)

Choice 5 — float64 and honest precision

float32 would double throughput on paper. Rejected: squaring amplifies rounding, deep orbits would visibly kink, and — decisive — the overflow-to-NaN hazard arrives sooner. The cos(x²) mutations already oscillate punishingly at |x| > 10; halving mantissa there produces visibly different pictures. For the same reason the escape radii for transcendental maps were set generously (|y|, |x|, or |z| at 100–1000) so the classifier divergence proofs still hold in floating point.

Back-of-envelope: the classic render moves ~4.4 billion plotted points at ~10 flops each ≈ 45 GFLOP, done in 185 s ≈ 0.25 GFLOP/s effective — one to two orders below the CPU’s arithmetic peak. The gap is the scatter: bincount and the compaction copies are memory-bound random traffic, not arithmetic. That gap is exactly what a GPU would close.

Quality control without eyes

Renders were judged by numbers before anyone saw pixels: mean luminance (0.05–0.2 is the balanced band), visible fraction (structure coverage), mirror-symmetry correlation (checked against each formula’s equivariance prediction), center of mass (a lopsided CoM on a symmetric map means a bug, on an asymmetric map means the mutation worked), and region brightness probes (body/head/antenna/corner). Every out-of-band image was re-toned from its cached histogram — the render never re-ran. That loop — measure, re-tone, measure — is the quiet hero of the whole project.

What would make it better

Smarter sampling

Uniform sampling wastes shots on uninteresting countryside. Boundary-weighted importance sampling, or Metropolis-Hastings mutation of seeds (the classic technique for Buddhabrot: propose new c near old c, keep proposals whose orbits hit the frame), concentrates samples exactly where the picture is — typically 10–50× effective sample efficiency.

GPU backend

A ~100-line CUDA kernel (one block per sample batch, atomicAdd into a texture) would turn “minutes” into “seconds”, unlock 8K and animation. The two-phase structure dissolves: classify and plot in the same pass.

Animation pipeline

The cached-histogram design already supports keyframed tone-maps; a zoom/rotation film needs only re-windowed histograms — resample the same orbit data through a different affine window.

Proper imaging pipeline

HDR EXR output, filmic tone-mapping (ACES-ish) instead of gamma-only, per-channel p95 anchors for chroma balance, and optional wavelet denoise to smooth Monte-Carlo grain without losing filigree.
